# Contributing to .github

Thanks for working on this project. This guide covers how changes get in.

## Branches and pull requests

- `main` is the protected branch. Do not push directly to it.
- Create a branch for each change, for example `feature/short-name` or `fix/short-name`.
- Open a pull request into `main` and ask a teammate to review it before merging.
- Keep pull requests small and focused on one change. Describe what changed and why.

## Before you open a pull request

This is the organization profile repository. Changes appear on the organization page. Check the Markdown renders correctly on GitHub before merging.

- Do not commit secrets, tokens, environment URLs with credentials, or real personal data.
- Keep generated output (build folders, `.out`, `dist`) out of git unless the project says otherwise.

## Review

- At least one approving review is expected before merge.
- Reviewers check correctness, tests, and whether the change fits the project's structure.
- Resolve review comments in the same pull request, or explain in the thread why you did not.

## Questions

Open an issue in this repository, or ask in the team channel.
